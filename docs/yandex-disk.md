# Интеграция с Яндекс.Диском — канал тест → прод

Реализовано по ТЗ «Экспорт в Яндекс.Диск» (2026-09-18). Назначение — не
кнопка «выгрузить архив», а канал переноса файла экспорта между двумя
независимыми инсталляциями (тестовой и боевой), между которыми нет прямой
связи.

## Сценарий

1. На **тесте** администратор выгружает/готовит элемент инфоблока как обычно.
   На странице прогресса экспорта, если интеграция включена, рядом с кнопкой
   «Скачать архив» появляется кнопка **«Выгрузить в Яндекс.Диск»**.
2. На **проде** администратор открывает страницу «Импорт» — если Диск подключён, под формой сразу показан список
   файлов в папке обмена (кнопка **«Проверить Диск»** обновляет его). Список не показывается, пока на странице
   принятый архив (после «Проверить архив»/«Импортировать»); если Диск недоступен, над формой — ошибка, а обычная
   загрузка `.zip` работает.
3. Администратор выбирает файл и нажимает **«Импортировать»** — файл
   скачивается с Диска и передаётся в тот же процесс импорта, что и при
   ручной загрузке `.zip`. Кнопка отправляет основную форму страницы (атрибут `form`, шаг и файл — в `formaction`):
   инфоблок, родительский раздел и галки берутся такими, какие они в форме в момент нажатия.

## Очистка папки обмена

На странице подключения Диска (`admin/yandex_disk.php`, только администратор) — кнопка **«Очистить папку «…» на
Диске (файлов: N)»** рядом с «Отключить» (`Client::clearFolder()`):

- Все файлы папки обмена перемещаются в **Корзину Яндекс.Диска** (`DELETE /v1/disk/resources`, `permanently=false`) —
  оттуда их можно восстановить. Сама папка и вложенные папки остаются.
- Папка общая для всех сайтов, подключённых к этому Диску (тест и прод): файлы пропадут из списка для импорта везде,
  поэтому перед очисткой — подтверждение. История импортов (`ImportedFileTable`) на сайтах не меняется.
- Если папка обмена в настройках указывает на корень Диска (`/`, `disk:/`), очистка запрещена — иначе она вычистила
  бы весь Диск.
- Файлы удаляются по одному запросу на файл; если какой-то удалить не удалось, страница показывает, сколько удалено и
  какие файлы остались (с причиной). Пустую папку очищать нечего — кнопки нет.

## Список файлов на Диске

- Файлы идут от новых к старым (до 200 штук), в колонке **«№»** номер растёт со временем изменения файла: у самого
  нового — наибольший (номер — позиция в показанном списке, а не постоянный идентификатор файла).
- Дата «Изменён» показывается во времени сервера (Диск отдаёт её в UTC).
- Архивы, уже импортированные на этой инсталляции, выделены зелёным; в колонке **«Импортирован на этом сайте»** —
  дата последнего импорта, целевой инфоблок и число импортов, если их было несколько. Импортировать такой файл
  можно и повторно.
- Признак берётся из истории импортов `lib/ImportedFileTable.php` (таблица `vspace_ibexport_imported_file`): запись
  на каждый успешно завершённый импорт, бессрочно (журнал импорта удаляется через «Срок хранения» вместе с рабочим
  каталогом, история — нет). Архив узнаётся по MD5 содержимого — Диск отдаёт его в списке файлов, а при приёме
  архива модуль сохраняет MD5 в рабочем каталоге (`lib/Import/SourceInfo.php`, файл `source.json`). Поэтому
  отмечается и архив, импортированный ручной загрузкой `.zip`, а файл с тем же именем, но другим содержимым — нет.
- Учитываются импорты, выполненные начиная с версии 1.3.0; более ранние в истории не записаны.

Оба шага — полностью ручные и независимые по времени; недоступность сети
или API Яндекс.Диска не влияет на обычный (файловый) импорт на проде и на
обычный экспорт/скачивание архива на тесте — см. `admin/import.php`
(ветки `STEP=disk_list`/`disk_import` отделены от `STEP=validate`/`run`) и
`admin/progress.php` (отдельная форма на `yandex_disk_upload.php`).

## Настройка

**Настройки → Контент → Экспорт/импорт инфоблоков → Яндекс.Диск**
(только для администратора — `admin/yandex_disk.php`):

- Токен приложения Яндекс.Диска (OAuth) — хранится в БД в зашифрованном
  виде (`\Bitrix\Main\Security\Cipher` + `crypto_key` из
  `bitrix/.settings.php`, тем же приёмом, что ядро использует для паролей
  SMTP в `Bitrix\Main\Mail\Internal\SenderTable`).
- Папка обмена на Диске (по умолчанию `/vspace.ibexport`).
- Флаг «Интеграция включена».

**Важно:** тест и прод должны быть подключены к **одному и тому же**
аккаунту Яндекс.Диска (или как минимум к одной согласованной папке) —
иначе прод не увидит файлы, выгруженные с теста. Это организационное
требование к настройке, не техническое ограничение модуля. Токен у каждой
инсталляции свой — общий аккаунт Диска не означает общий токен.

## Компоненты

Весь код, специфичный для Яндекс.Диска, живёт в одном namespace
`Vspace\Ibexport\YandexDisk` (каталог `lib/YandexDisk/`):

- `lib/YandexDisk/Client.php` — обёртка над REST API
  `cloud-api.yandex.net/v1/disk`: `checkConnection()`, `ensureFolder()`,
  `uploadFile()`, `listFiles()`, `downloadFile()`.
- `lib/YandexDisk/Exception.php` — ошибка обращения к Диску (сеть,
  авторизация, код ошибки API).
- `lib/YandexDisk/Http/TransportInterface.php` +
  `lib/YandexDisk/Http/BitrixHttpTransport.php` — вся сетевая логика
  клиента идёт через этот интерфейс. Это сделано ради юнит-тестируемости
  (см. `tests/YandexDisk/ClientTest.php`): с поддельным транспортом можно
  проверить сборку URL, разбор ответов API и обработку ошибок без реальных
  запросов к Яндексу и без поднятия ядра Bitrix. Боевая реализация —
  тонкая обёртка над штатным `\Bitrix\Main\Web\HttpClient`.
- `lib/YandexDisk/Settings.php` — токен и папка обмена: `getToken()`/
  `setToken()` (шифрование), `getFolder()`/`setFolder()`, `hasToken()`,
  `clearToken()`. Флаг «включена ли интеграция»
  (`isYandexDiskEnabled()`/`setYandexDiskEnabled()`) остаётся в общем
  `lib/Options.php` — это просто переключатель наравне с другими опциями
  модуля, а не специфика самого Диска.
- `lib/YandexDisk/ImportSource.php` — источник импорта «с Диска»:
  `listDiskFiles()`, `prepareFromDisk()`. Используются из
  `admin/import.php` (`STEP=disk_list`/`disk_import`), делят общую логику
  распаковки/валидации ZIP с обычной загрузкой файла
  (`Importer::extractAndValidate()` — публичный метод именно ради этого).
- `admin/yandex_disk.php` — страница настройки/статуса подключения.
- `admin/yandex_disk_upload.php` — действие «Выгрузить в Яндекс.Диск»
  (POST, вызывается с `admin/progress.php`).

Точки входа админки (`admin/yandex_disk.php`, `admin/yandex_disk_upload.php`
и их обёртки в `install/admin/`) физически остаются в общей структуре
`admin/`/`install/admin/` — только их `use`-импорты указывают на новый
namespace.

## Сетевые сбои и повторные попытки

Сам файл передаётся не через `cloud-api.yandex.net`, а по одноразовой ссылке на один из узлов Диска
(`uploader*.disk.yandex.net`, `downloader*.disk.yandex.net`). У этих узлов есть и IPv4-, и IPv6-адрес с коротким
временем жизни DNS-записи (у IPv6 — 30 с). PHP перебирает адреса узла по очереди и сообщает ошибку последней попытки,
поэтому на сервере без IPv6 любой кратковременный сбой узла выглядит как
`stream_socket_client(): Unable to connect to tcp://uploader….disk.yandex.net:443 (Network is unreachable)`:
IPv4-попытка не удалась, а IPv6 с этого сервера недоступен в принципе.

Поэтому `Client::uploadFile()` и `downloadFile()` при сетевом сбое (запрос не дошёл до сервера) повторяют передачу
до `Client::TRANSFER_ATTEMPTS` раз (3) с паузой 1 и 2 с, каждый раз запрашивая новую ссылку — она часто ведёт на
другой узел. HTTP-ошибки (ответ получен, но код не 2xx) не повторяются. Если не удались все попытки, в сообщении
указано их число; архив на сайте при этом не страдает — кнопку «Выгрузить в Яндекс.Диск» можно нажать ещё раз.

## Почему не штатный механизм Bitrix

Готового коннектора для Яндекс.Диска в Bitrix нет — `CCloudStorage`
поддерживает только S3-совместимые хранилища, Google Cloud Storage и
Azure. Сама интеграция с Яндекс.Диском поэтому неизбежно собственная, но
построена на штатном HTTP-клиенте ядра (`\Bitrix\Main\Web\HttpClient`) и
штатном механизме шифрования секретов (`\Bitrix\Main\Security\Cipher` +
`crypto_key`), а не на самодельных аналогах.

## Ограничения (сознательно вне рамок, см. ТЗ, раздел 9)

- Проверка Диска и импорт — только по ручному нажатию, без расписания/вебхука.
- Автоматического импорта без подтверждения администратора нет.
- Автоматической выгрузки на тесте сразу после экспорта нет — только кнопка.
- Двусторонней синхронизации (отметки «уже импортирован», авто-удаление с
  Диска после импорта) нет — повторная выгрузка/импорт того же файла
  обрабатывается вручную администратором.
- Один активный токен на инсталляцию, без нескольких подключённых Дисков.
- Лимит размера файла — 1 ГБ (бесплатный тариф Диска), проверяется до
  запроса к API.
