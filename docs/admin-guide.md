# Инструкция администратора — модуль "Экспорт/импорт элементов и разделов инфоблоков"

Модуль: `vspace.ibexport`

## Установка

1. Скопировать содержимое каталога модуля в `local/modules/vspace.ibexport/` (или `bitrix/modules/vspace.ibexport/`).
2. В админке зайти в **Настройки → Настройки продукта → Модули**, найти "Экспорт элементов и разделов инфоблоков" и установить.
3. При установке модуль:
   - создаёт таблицы `vspace_ibexport_job` и `vspace_ibexport_import_job` (задания/журналы выгрузок и загрузок);
   - копирует служебные страницы в `/bitrix/admin/` (`vspace_ibexport_*.php`);
   - регистрирует пункт меню "Экспорт/импорт инфоблоков" в разделе "Контент";
   - регистрирует агенты периодической очистки временных файлов (отдельно для экспорта и для импорта).
4. Модулю требуется установленный модуль "Информационные блоки" (iblock).

## Где искать функциональность

- **Меню админки → Контент → Экспорт/импорт инфоблоков → Новая выгрузка** — страница ручного запуска экспорта (раздел 7.3 ТЗ).
- **Меню админки → Контент → Экспорт/импорт инфоблоков → Журнал выгрузок** — история всех выгрузок текущего пользователя (администратору видны все).
- **Меню админки → Контент → Экспорт/импорт инфоблоков → Импорт** — загрузка ранее выгруженного архива и создание/обновление элементов/разделов в выбранном инфоблоке (см. `docs/import-format.md`).
- **Меню админки → Контент → Экспорт/импорт инфоблоков → Журнал импорта** — история запусков импорта.
- **Меню админки → Контент → Экспорт/импорт инфоблоков → Яндекс.Диск** (только администратор) — подключение канала переноса файлов между независимыми инсталляциями (тест ↔ прод) через Яндекс.Диск, см. `docs/yandex-disk.md`.
- **Список элементов / список разделов инфоблока** — в контекстное меню действий строки (там же, где "Изменить", "Копировать", "Удалить") добавляется пункт "Экспорт" (раздел 7.1/7.2 ТЗ). Он ведёт на ту же форму ручного экспорта с предзаполненными полями.

> Пункт "Экспорт" добавляется через штатное событие ядра `main::OnAdminListDisplay` (см. `lib/Integration/AdminListIntegration.php`) — оно вызывается списком элементов/разделов (`iblock_element_admin.php`, `iblock_section_admin.php`, построены на `CAdminUiList`) прямо перед выводом и передаёт сам объект списка со всеми строками, так что пункт действия строки добавляется через штатный API строки (`$row->aActions[]`), тем же способом, каким ядро добавляет собственные пункты меню — без парсинга HTML через JS и без риска сломать разметку темы.

## Как запустить экспорт

1. Открыть "Новая выгрузка".
2. Выбрать инфоблок (в списке — только инфоблоки, доступные текущему пользователю на чтение).
3. Указать тип сущности — элемент или раздел.
4. Указать ID или символьный код сущности.
5. Для раздела — выбрать режим:
   - **Только этот раздел** — сам раздел и его элементы верхнего уровня, без вложенных подразделов (FR-2).
   - **Раздел со всеми вложенными подразделами** — полное дерево (FR-3).
6. Отметить чекбоксы "Выгружать файлы" и "Только активные" при необходимости.
7. Нажать "Рассчитать объём" — модуль покажет, сколько разделов и элементов попадёт в выгрузку.
8. Нажать "Запустить экспорт".

Небольшие выгрузки (по умолчанию — до 300 узлов суммарно, настраивается) завершаются практически сразу на странице прогресса. Большие выгрузки продолжают выполняться в фоне (через агент Bitrix) даже если закрыть вкладку браузера — при следующем заходе на страницу прогресса (ссылка есть в журнале выгрузок) будет виден актуальный статус.

## Скачивание результата

На странице прогресса после завершения появляется кнопка "Скачать архив". Архив — ZIP-файл с `export.xml` и (если включена опция) подкаталогом `files/`.

Имя файла архива формируется из символьного кода инфоблока, типа и кода/названия сущности и (для разделов) режима, например `news_element_glavnaya-novost_2043_job17.zip` или `news_section_akcii_45_tree_job18.zip` — по имени файла в списке скачанных архивов видно, что внутри, без открытия XML. Номер задания в конце гарантирует уникальность имени при повторных выгрузках одной и той же сущности.

## Как запустить импорт

Подробные правила сопоставления, что переносится как есть, а что требует существующих определений в целевом инфоблоке — см. `docs/import-format.md`. Кратко:

1. Открыть "Импорт".
2. Выбрать инфоблок, **в который** нужно импортировать (не обязан совпадать с исходным).
3. Прикрепить `.zip`-архив, выгруженный этим же модулем.
4. При необходимости указать "Родительский раздел" (ID или код в целевом инфоблоке) — куда поместить импортируемое дерево разделов; не используется для архивов с одним элементом.
5. Отметить "Обновлять существующие по символьному коду" при необходимости (по умолчанию включено). Если у элементов/разделов нет символьного кода, включите "Сопоставлять по XML_ID, если нет символьного кода" (по умолчанию выключено) — тогда такие записи ищутся в целевом инфоблоке по внешнему коду.
6. Нажать "Проверить архив" — модуль распакует архив, покажет режим и количество разделов/элементов, а под формой — таблицу "Что будет импортировано": для каждой записи тип, ID в архиве, XML_ID, символьный код, название, активность, раздел в архиве, число файлов и свойств, найденное совпадение в целевом инфоблоке (по коду / по XML_ID / не найдено / нет ключа сопоставления) и ожидаемое действие (создать / обновить / пропустить). Показываются первые 200 записей. Действие считается по отметкам формы на момент проверки; при запуске учитываются отметки, выставленные в форме.
7. Нажать "Запустить импорт".

Как и экспорт, небольшие импорты завершаются практически сразу на странице прогресса, большие — продолжают выполняться в фоне через агент Bitrix.

## Перенос через Яндекс.Диск (тест ↔ прод)

Если между инсталляциями нет прямой связи, файл можно передать через Яндекс.Диск — см. подробности в `docs/yandex-disk.md`. Коротко:

1. Настроить подключение на обеих инсталляциях: **Яндекс.Диск** в меню модуля (только администратор) — свой токен на каждой, но один и тот же аккаунт/папка на Диске у обеих.
2. На инсталляции-источнике: на странице прогресса завершённого экспорта — кнопка "Выгрузить в Яндекс.Диск" рядом со "Скачать архив".
3. На инсталляции-приёмнике: на странице "Импорт" — кнопка "Проверить Диск" показывает список файлов, "Импортировать" у нужного файла запускает обычный процесс импорта.

Оба шага — ручные и независимые по времени; недоступность Диска не мешает обычному скачиванию архива или обычной загрузке `.zip`.

## Права доступа

Экспорт доступен пользователям с правом на чтение соответствующего инфоблока (стандартные права модуля "Информационные блоки"), либо пользователям с отдельным правом операции `vspace_ibexport_export`, либо администраторам. См. `lib/Rights.php`.

Импорт (он пишет данные) требует права **редактирования** соответствующего инфоблока, либо отдельного права операции `vspace_ibexport_import`, либо администратора.

## Настройки модуля

Настройки → Настройки продукта → Модули → Экспорт элементов и разделов инфоблоков → шестерёнка:

| Параметр | Смысл | По умолчанию |
| --- | --- | --- |
| Размер страницы выборки | Сколько записей читается из БД за один запрос | 200 |
| Порог фонового режима | Суммарное число узлов, выше которого выгрузка/импорт выполняется в фоне | 300 |
| Бюджет тика, сек | Максимальное время одного шага фоновой обработки | 12 |
| Срок хранения, часов | Через сколько часов временные файлы (и архив экспорта) удаляются автоматически | 24 |
| Выгружать файлы по умолчанию | Начальное состояние чекбокса в форме экспорта | Да |
| Только активные по умолчанию | Начальное состояние чекбокса в форме экспорта | Нет |
| Обновлять существующие по коду по умолчанию | Начальное состояние чекбокса в форме импорта | Да |

## Журнал и ошибки

Каждый запуск экспорта — это строка в таблице `vspace_ibexport_job`, видимая на странице "Журнал выгрузок": кто запустил, когда, какой режим, статус, сколько разделов/элементов обработано, размер архива. Каждый запуск импорта — аналогично строка в `vspace_ibexport_import_job`, видимая на странице "Журнал импорта": целевой инфоблок, режим, статус, сколько создано/обновлено/пропущено. Дополнительно ключевые события (успех/ошибка) пишутся в `CEventLog` с `AUDIT_TYPE_ID = VSPACE_IBEXPORT_DONE` / `VSPACE_IBEXPORT_ERROR` (экспорт) и `VSPACE_IBIMPORT_DONE` / `VSPACE_IBIMPORT_ERROR` (импорт) — их можно посмотреть в **Настройки → Инструменты → Журнал событий**.

Частичные сбои (например, отсутствующий файл свойства, не найденный по коду раздел или вариант списка) не прерывают выгрузку/импорт — такие случаи копятся в поле `WARNINGS_JSON` записи задания и не мешают завершить обработку остальных элементов (раздел 9 ТЗ).

## Временные файлы

Файлы конкретной выгрузки лежат в `/upload/tmp/vspace.ibexport/job_<идентификатор>/`, файлы конкретной загрузки импорта — в `/upload/tmp/vspace.ibexport/import_<идентификатор>/`. Удаляются автоматически соответствующим агентом очистки через настраиваемый TTL после завершения (по умолчанию 24 часа); для импорта агент также убирает каталоги, оставшиеся от "проверенных, но не запущенных" загрузок. Ручное удаление раньше срока безопасно — на активную выгрузку/импорт это не повлияет, влияет только на уже скачанные/незавершённые архивы.
