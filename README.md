# vspace.ibexport

Модуль для 1С-Битрикс (Bitrix Framework): экспорт элементов, разделов и
деревьев разделов инфоблока в ZIP+XML архив и обратный импорт из такого
архива в тот же или другой инфоблок — с интерфейсом в стиле стандартной
админки Bitrix и фоновой обработкой больших объёмов данных.

## Возможности

- **Экспорт**:
  - одного элемента (со всеми его разделами, свойствами и файлами);
  - одного раздела без вложенных подразделов;
  - раздела со всем деревом вложенных подразделов и элементов (элемент попадает
    в выгрузку под каждым разделом дерева, к которому привязан, — основной или
    дополнительной привязкой).
  - Пункт "Экспорт" добавляется прямо в контекстное меню строки списка
    элементов/разделов инфоблока в админке (через штатное событие ядра
    `main::OnAdminListDisplay`, без JS/DOM-хаков).
- **Импорт** — загрузка ранее выгруженного архива и создание/обновление
  элементов и разделов в выбранном инфоблоке (не обязательно исходном).
  Сопоставление при повторном импорте — по символьному коду (`CODE`); для
  записей без кода — по `XML_ID` (отдельная опция формы, по умолчанию выключена).
  Свойства-привязки к элементам/разделам переносятся по коду (или XML_ID)
  связанной записи, а не по ID; описания значений свойств и даты (в ISO 8601)
  переносятся между сайтами с разными форматами. Переносятся и собственные
  SEO-шаблоны записей (вкладка «SEO»: мета-теги, заголовок страницы, alt/title
  картинок).
- Небольшие выгрузки/загрузки выполняются синхронно и сразу показывают
  результат; объёмные — уходят в фон (агент Bitrix, тик-бюджет,
  возобновление после разрыва) и не блокируют браузер.
- Журналы выгрузок и импортов, права доступа на уровне инфоблока и уровни
  доступа к модулю (вкладка "Доступ" в настройках), настраиваемые лимиты и
  TTL временных файлов; временные файлы — в штатном каталоге временных файлов
  Bitrix, закрытом от доступа из веба.
- **Канал через Яндекс.Диск** между независимыми инсталляциями (например,
  тест → прод): архив экспорта уходит на Диск сразу после выгрузки (настройка
  модуля, по умолчанию включена; есть и ручная кнопка), на другой инсталляции
  импортируется из списка файлов Диска. Недоступность Диска не мешает обычному
  экспорту/импорту.

Подробное описание XML-формата — [docs/xml-format.md](docs/xml-format.md),
правила импорта — [docs/import-format.md](docs/import-format.md),
интеграция с Яндекс.Диском — [docs/yandex-disk.md](docs/yandex-disk.md),
инструкция администратора — [docs/admin-guide.md](docs/admin-guide.md).

## Требования

- Bitrix Framework (модуль "Информационные блоки" / `iblock` обязателен).
- PHP 8.1+.

## Установка

1. Скопировать содержимое репозитория в `local/modules/vspace.ibexport/`
   (или `bitrix/modules/vspace.ibexport/`).
2. В админке: **Настройки → Настройки продукта → Модули** → найти
   "Экспорт/импорт элементов и разделов инфоблоков" → установить.
3. При установке модуль создаёт служебные таблицы, копирует страницы в
   `/bitrix/admin/`, регистрирует пункт меню, агенты автоочистки
   временных файлов и уровни доступа к модулю.

Обновление уже установленного модуля (переустановка с сохранением таблиц
либо `InstallDB()`/`InstallTasks()` из командной PHP-строки) — см.
[docs/admin-guide.md](docs/admin-guide.md), "Обновление уже установленного модуля".

## Где искать функциональность в админке

Меню **Контент → Экспорт/импорт инфоблоков**:

- **Новая выгрузка** — запуск экспорта.
- **Журнал выгрузок** — история экспортов.
- **Импорт** — загрузка архива и запуск импорта (или проверка/импорт файла
  с подключённого Яндекс.Диска).
- **Журнал импорта** — история импортов.
- **Яндекс.Диск** (только администратор) — подключение токена и папки
  обмена для канала переноса файлов между инсталляциями.

Настройки модуля (размер страницы выборки, порог фонового режима, TTL
временных файлов и т.д.) — в настройках модуля в панели управления.

## Архитектура

- `lib/Exporter.php` / `lib/Importer.php` — тонкие фасады (публичный API
  модуля): расчёт объёма, создание задания, тик агента/AJAX-опроса. Сама
  работа делегирована коллабораторам ниже.
- `lib/AbstractJobTable.php` — общая основа ORM-таблиц заданий
  (`DataManager`): служебные поля, `STATUS_*`, атомарный захват задания на
  тик (`tryLock()`/`unlock()`), расчёт процента, срок хранения и перевод
  брошенных заданий в ошибку (`failAbandoned()`). Наследники:
  `lib/JobTable.php` (экспорт) и `lib/ImportJobTable.php` (импорт) — только
  собственные поля. `lib/ImportedFileTable.php` — бессрочная история
  импортированных архивов (по MD5, его сохраняет `lib/Import/SourceInfo.php`):
  по ней список файлов на Яндекс.Диске отмечает уже импортированные.
- `lib/TickRunner.php` — общий движок фонового задания (шаблон тика:
  проверка статуса, блокировка, `try/catch/finally`, перепланирование
  `CAgent`, `toProgress()`), одинаков для экспорта и импорта; конкретный
  шаг тика ему передаётся колбэком. `lib/JobEventLog.php` — запись в
  журнал событий Bitrix.
- `lib/Export/` — экспорт: `ExportStep` (один тик: стадии
  `init → traverse → finalize`), `SectionTreeWalker` (возобновляемый
  тик-бюджетный DFS-обход дерева разделов), `SectionWriter` /
  `ElementWriter` / `FileRefWriter` (XML-узлы), `ArchiveBuilder` (ZIP),
  `TreeSourceInterface` + `BitrixTreeSource` (источник дерева — граница
  для тестов), `UserFieldExport` (правила выгрузки `UF_*` разделов), `ExportContext`.
- `lib/Import/` — импорт: `ImportStep` (один тик), `SectionTreeWalker`
  (зеркальный обход по распакованному XML), `SectionImporter` /
  `ElementImporter` (создание/обновление записи), `PropertyResolver`
  (XML-описание свойств → массив для `SetPropertyValuesEx`) с границами
  `PropertySourceInterface` / `FileArrayFactoryInterface`, `ImportReport`
  (счётчики и предупреждения), `ImportContext`; `ImportPreview` —
  предпросмотр перед запуском (записи архива, совпадения в целевом
  инфоблоке, ожидаемое действие) с границей `ExistingRecordFinderInterface` /
  `BitrixExistingRecordFinder` (она же ищет связанные записи свойств-привязок);
  `ArchiveFileRef` — какие записи ZIP распаковываются и какие ссылки на файлы
  архива допустимы.
- `lib/TmpStorage.php` — рабочие каталоги заданий в штатном каталоге временных
  файлов Bitrix (`CTempFile::GetAbsoluteRoot()`): случайные имена, `.htaccess`
  с запретом доступа, очистка брошенных каталогов и каталога версий до 1.1.0.
- `lib/DateValue.php` — даты в `export.xml` в ISO 8601 и обратно в формат сайта.
- `lib/SeoTemplates.php` — собственные SEO-шаблоны записи (`InheritedPropertyTable`):
  чтение для экспорта, блок `<seo>` в XML, разбор и значение `IPROPERTY_TEMPLATES` для импорта.
- `lib/WalkResult.php` — итог одной порции обхода (стек + обработанные
  узлы), общий для экспорта и импорта.
- `lib/TraversalFrame.php` — кадр стека обхода как value-объект
  (типизированные поля, `toArray()`/`fromArray()`); `Export\ExportFrame` и
  `Import\ImportFrame` — конкретные кадры экспорта и импорта. Массивный
  формат кадра — прежний формат `STATE_JSON` (обратно читаем: задания,
  начатые до рефакторинга, продолжаются как есть).
- `lib/Integration/AdminListIntegration.php` — внедрение пункта "Экспорт" в
  списки элементов/разделов через `main::OnAdminListDisplay`.
- `lib/Rights.php` — проверка прав на экспорт/импорт по конкретному
  инфоблоку и операций модуля (`vspace_ibexport_export`/`_import`); уровни
  доступа — `GetModuleTasks()` в `install/index.php`, названия —
  `admin/task_description.php`, `admin/operation_description.php`.
- `lib/YandexDisk/` — вся интеграция с Яндекс.Диском в одном namespace
  (`Vspace\Ibexport\YandexDisk`): `Client.php` (REST API поверх штатного
  `HttpClient`), `Settings.php` (токен/папка обмена), `ImportSource.php`
  (источник импорта "с Диска"), `Http/` (транспорт клиента), см.
  [docs/yandex-disk.md](docs/yandex-disk.md).
- `lib/IblockListProvider.php` — список инфоблоков, доступных
  пользователю (`CIBlock::GetList` + проверка права колбэком), общий для
  страниц экспорта и импорта. `lib/Admin/AdminMessages.php` — единый вывод
  сообщений админки через штатный `CAdminMessage`.
- `lib/Admin/ExportPageController.php` / `ImportPageController.php` — обработка
  запроса страниц экспорта и импорта (`handle(HttpRequest): array`): разбор
  параметров, валидация, права, шаги `estimate`/`run` и
  `validate`/`disk_list`/`disk_import`/`run`, редирект на страницу прогресса.
  HTML не формируют — возвращают данные для отрисовки формы.
- `admin/` — страницы админки (`CAdminTabControl`, `CAdminList`); `export.php`
  и `import.php` — тонкие обёртки: контроллер + вёрстка формы.
  `admin/css/vibx.css` — общие стили страниц модуля (`.vibx-note` и др.),
  подключаются штатным `$APPLICATION->SetAdditionalCSS()`.
- `options.php` — настройки модуля (`CAdminTabControl`: параметры с проверкой
  границ и штатная вкладка "Доступ" — `group_rights2.php`).
- Тексты сообщений `lib/` — в `lang/{ru,en}/lib/…` (`Loc::loadMessages(__FILE__)`).

## Тесты

Юнит-тесты (PHPUnit, 147 тестов) работают без сети и без поднятия ядра
Bitrix — за счёт тонких интерфейсов на границе с Bitrix API (образец —
`YandexDisk\Http\TransportInterface`) и поддельных реализаций в `tests/`;
вместо `Bitrix\Main\Localization\Loc` — заглушка `tests/Stub/Loc.php`, читающая
языковые файлы модуля:

- `YandexDisk\Client` — сборка URL, разбор ответов API, обработка ошибок,
  лимит размера файла (поддельный HTTP-транспорт); разбор HTTP-редиректов
  в `YandexDisk\Http\BitrixHttpTransport::resolveRedirectUrl()`.
- `TraversalFrame` (`ExportFrame`/`ImportFrame`) — round-trip
  `toArray()`/`fromArray()`, порядок ключей, чтение `STATE_JSON`, записанного
  до рефакторинга.
- `Export\SectionTreeWalker` — переходы между фазами, постраничное чтение
  элементов и подразделов, передача раздела писателю элементов, `section_single`,
  возобновление после разрыва на каждом шаге
  (поддельные `TreeSourceInterface` и писатели, часы подменены счётчиком).
- `Import\SectionTreeWalker` — то же для импорта на настоящем SimpleXML
  (поддельные импортёры).
- `Import\PropertyResolver` — типы `L`/`F`/`E`/`G`/текстовые, описания значений,
  очистка пустых свойств, нет определения свойства, нет варианта списка, нет
  файла в архиве, недопустимые ссылки на файлы, привязки по коду/XML_ID и архивы
  прежнего формата (`PropertySourceInterface`, `FileArrayFactoryInterface`,
  `ExistingRecordFinderInterface`).
- `Import\ArchiveFileRef` — допустимые ссылки на файлы и распаковываемые записи ZIP.
- `DateValue::parseIso()` — разбор дат ISO 8601 из архива.
- Языковые файлы — у каждого `Loc::getMessage()` в коде есть ключ на русском и
  английском, наборы ключей ru/en совпадают.
- `Import\ImportReport` — счётчики и предупреждения (одинаковые считаются один раз).
- `WarningList` — объединение одинаковых предупреждений задания и лимит размера `WARNINGS_JSON`.
- `Export\UserFieldExport` — какие `UF_*`-поля раздела и как выгружаются; `Import\SectionImporter::parseUserFields()` — их разбор при импорте.
- `Import\ImportPreview` — порядок строк, контекст раздела, счётчики файлов и
  свойств, выбор ключа сопоставления и действия, предупреждения (другое
  название, неоднозначный XML_ID), усечение по лимиту, повторное вхождение
  элемента из нескольких разделов ("добавить привязку")
  (поддельный `ExistingRecordFinderInterface`).
- `Import\AbstractNodeImporter::matchFilter()` — выбор ключа сопоставления (`CODE` / `XML_ID` / нет).

Общий движок тика (`TickRunner`), таблицы заданий и страницы админки
требуют ядра Bitrix и юнит-тестами не покрыты. Запуск:

```bash
composer install
vendor/bin/phpunit
```
