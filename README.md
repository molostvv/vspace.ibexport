# vspace.ibexport

Модуль для 1С-Битрикс (Bitrix Framework): экспорт элементов, разделов и
деревьев разделов инфоблока в ZIP+XML архив и обратный импорт из такого
архива в тот же или другой инфоблок — с интерфейсом в стиле стандартной
админки Bitrix и фоновой обработкой больших объёмов данных.

## Возможности

- **Экспорт**:
  - одного элемента (со всеми его разделами, свойствами и файлами);
  - одного раздела без вложенных подразделов;
  - раздела со всем деревом вложенных подразделов и элементов.
  - Пункт "Экспорт" добавляется прямо в контекстное меню строки списка
    элементов/разделов инфоблока в админке (через штатное событие ядра
    `main::OnAdminListDisplay`, без JS/DOM-хаков).
- **Импорт** — загрузка ранее выгруженного архива и создание/обновление
  элементов и разделов в выбранном инфоблоке (не обязательно исходном).
  Сопоставление при повторном импорте — по символьному коду (`CODE`).
- Небольшие выгрузки/загрузки выполняются синхронно и сразу показывают
  результат; объёмные — уходят в фон (агент Bitrix, тик-бюджет,
  возобновление после разрыва) и не блокируют браузер.
- Журналы выгрузок и импортов, права доступа на уровне инфоблока,
  настраиваемые лимиты и TTL временных файлов.
- **Канал через Яндекс.Диск** между независимыми инсталляциями (например,
  тест → прод): выгрузка готового архива в Яндекс.Диск с одной
  инсталляции и импорт с Диска на другой, отдельными ручными кнопками, не
  влияющими на обычный экспорт/импорт при недоступности Диска.

Подробное описание XML-формата — [docs/xml-format.md](docs/xml-format.md),
правила импорта — [docs/import-format.md](docs/import-format.md),
интеграция с Яндекс.Диском — [docs/yandex-disk.md](docs/yandex-disk.md),
инструкция администратора — [docs/admin-guide.md](docs/admin-guide.md).

## Требования

- Bitrix Framework (модуль "Информационные блоки" / `iblock` обязателен).
- PHP 8.1+.

## Установка

1. Скопировать содержимое репозитория в `local/modules/vspace.ibexport/`
   (или `bitrix/modules/vspace.ibexport/`).
2. В админке: **Настройки → Настройки продукта → Модули** → найти
   "Экспорт/импорт элементов и разделов инфоблоков" → установить.
3. При установке модуль создаёт служебные таблицы, копирует страницы в
   `/bitrix/admin/`, регистрирует пункт меню и агенты автоочистки
   временных файлов.

## Где искать функциональность в админке

Меню **Контент → Экспорт/импорт инфоблоков**:

- **Новая выгрузка** — запуск экспорта.
- **Журнал выгрузок** — история экспортов.
- **Импорт** — загрузка архива и запуск импорта (или проверка/импорт файла
  с подключённого Яндекс.Диска).
- **Журнал импорта** — история импортов.
- **Яндекс.Диск** (только администратор) — подключение токена и папки
  обмена для канала переноса файлов между инсталляциями.

Настройки модуля (размер страницы выборки, порог фонового режима, TTL
временных файлов и т.д.) — в настройках модуля в панели управления.

## Архитектура

- `lib/Exporter.php` / `lib/Importer.php` — основная логика, тик-бюджетный
  DFS-обход дерева разделов с сохранением состояния обхода для
  возобновления после разрыва.
- `lib/JobTable.php` / `lib/ImportJobTable.php` — ORM-таблицы заданий
  (`DataManager`).
- `lib/Integration/AdminListIntegration.php` — внедрение пункта "Экспорт" в
  списки элементов/разделов через `main::OnAdminListDisplay`.
- `lib/Rights.php` — проверка прав на экспорт/импорт по конкретному
  инфоблоку.
- `lib/YandexDiskClient.php` + `lib/Http/*` — клиент REST API Яндекс.Диска
  поверх штатного `HttpClient`, см. [docs/yandex-disk.md](docs/yandex-disk.md).
- `admin/` — страницы админки (`CAdminTabControl`, `CAdminList`).

## Тесты

Юнит-тесты (PHPUnit, 23 теста) покрывают чистую логику `YandexDiskClient`
(сборка URL, разбор ответов API, обработка ошибок, лимит размера файла) с
поддельным HTTP-транспортом, а также разбор HTTP-редиректов в
`BitrixHttpTransport::resolveRedirectUrl()` (в т.ч. protocol-relative
`Location`, из-за которого аплоадер Яндекс.Диска ломал загрузку до
исправления) — без сети и без поднятия ядра Bitrix:

```bash
composer install
vendor/bin/phpunit
```
